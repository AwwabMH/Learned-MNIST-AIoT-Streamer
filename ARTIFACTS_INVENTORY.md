## File Descriptions by Category

### 1. Configuration & Metadata

#### `config.json` (1-2 KB)
**Format**: JSON  
**Contents**:
```json
{
  "train": { batch_size, epochs_full, epochs_tiny, lr, ... },
  "compression": { prune_full_amount, prune_tiny_amount, ... },
  "runtime": { deadline_ms, queue_capacity, memory_budget_mb, ... },
  "experiment": { seeds, rates_sps, arrival_modes, samples_per_scenario, ... },
  "device": "cuda",
  "quick_mode": true/false
}
```
**Use**: Version control, reproducibility, experiment metadata

---

### 2. Model Training & Catalog

#### `history_full.csv` (50-100 KB)
**Columns**: `epoch, train_loss, train_acc, test_loss, test_acc`  
**Rows**: Number of epochs (3-6)  
**Size**: 50-100 KB  
**Use**: Plot training curves to verify convergence

#### `history_tiny.csv` (50-100 KB)
**Columns**: Same as `history_full.csv`  
**Rows**: Number of epochs (3-5)  
**Use**: Verify lightweight model training

#### `model_catalog.csv` (10-20 KB)
**Columns**: `model_name, model_type, size_bytes, num_params, num_layers, flops`  
**Rows**: 10-15 (variant combinations: base, pruned, quantized)  
**Use**: Model size comparisons, FLOPs analysis

#### `model_static_metrics.csv` (20-50 KB)
**Columns**: `model_name, top1_accuracy, latency_edge_ms, latency_cloud_ms, energy_j`  
**Size**: One row per model variant  
**Use**: Accuracy-latency tradeoff analysis

#### `model_latency_benchmarks.csv` (10-30 KB)
**Columns**: `model_name, edge_compute_ms, model_load_ms, communication_ms, total_latency_ms`  
**Use**: Understand latency breakdown by component

---

### 3. Main Experiments

#### `main_logs_all.csv` (300-800 MB) ⚠️ LARGEST FILE
**Rows**: ~500K to 2M (1 per sample processed)  
**Columns** (59 total):
- Timing: `arrival_ms, queue_enter_ms, queue_wait_ms, model_load_ms, compute_ms, communication_ms, latency_ms`
- Decision: `policy, cascade_escalated, selected_model, edge_cloud, queue_depth`
- Correctness: `ground_truth_label, predicted_label, correct`
- Conditions: `seed, rate_sps, deadline_ms, arrival_mode, network_profile, memory_budget_mb`
- Cache: `cache_hit, models_in_cache, evictions_this_epoch`

**Use**: Deep analysis, per-sample debugging, statistical tests  
**Warning**: Can be 300-800 MB; load with `pd.read_csv(..., low_memory=False)` or chunking

#### `main_queue_traces_all.csv` (5-20 MB)
**Columns**: `timestamp, queue_depth, policy, rate_sps, seed, ...`  
**Use**: Visualize queue buildup/draining over time

#### `main_results_per_seed.csv` (50-200 KB)
**Rows**: ~100-500 (one per unique combination of policy, rate, deadline, mode, network)  
**Columns**: 
- `seed, policy, rate_sps, deadline_ms, arrival_mode, network_profile, memory_budget_mb`
- `top1_accuracy_mean, top1_accuracy_std`
- `latency_ms_mean, latency_ms_std`
- `deadline_met_ratio, drop_ratio, stale_ratio, timely_correct_ratio`

**Use**: Per-seed breakdowns for statistical error bars

#### `main_results_aggregated.csv` (50-200 KB)
**Columns**: Same as above but with `_mean` and `_std` (averaged across seeds)  
**Use**: Final ranking, policy comparison tables

#### `leaderboard_main.csv` (20-50 KB)
**Columns**: `policy, deadline_met_ratio_mean, latency_ms_mean, top1_accuracy_mean, rank`  
**Rows**: 5-7 (one per policy: FIFO, EDF, SRPT, Adaptive, Adaptive+Cascade, ...)  
**Use**: Quick ranking of which policy wins

---

### 4. Ablation Study

#### `ablation_logs_all.csv` (100-300 MB)
**Format**: Same as `main_logs_all.csv` but for ablation variants  
**Variants**: 
- Cascade: ON/OFF
- Cloud: ON/OFF
- Cache Penalty: ON/OFF

**Use**: Isolate impact of each component

#### `ablation_results_per_seed.csv` (20-50 KB)
**Rows**: One per (variant, seed, policy, rate, ...)  
**Columns**: Same metrics as main results  
**Use**: Evaluate ablation impact on accuracy/latency/deadline-met

#### `cascade_dispatch_composition.csv` (10-20 KB)
**Columns**: `rate_sps, deadline_ms, preview_accept_ratio, full_accept_ratio, cloud_accept_ratio, drop_ratio`  
**Use**: Understand cascade distribution (% escalated to fullmodel vs cloud vs dropped)

---

### 5. Learned Selector (Step 3)

#### `selector_training_data.csv` (10-30 MB)
**Rows**: ~20K-50K (training samples)  
**Columns**: 
- Features (14-20): `arrival_gap_ms, arrival_rate, queue_depth, memory_load, model_load_bandwidth, deadline_slack_ms, cache_hit_rate, ...`
- **Target**: `oracle_action` (one of 10 actions: which policy+setting combo)  
- Metadata: `seed, rate_sps, deadline_ms, ground_truth_label`

**Use**: Features for RandomForest training, feature importance analysis

#### `selector_oracle_rows.csv` (1-5 MB)
**Rows**: Subset with oracle labels  
**Use**: Verify oracle labeling correctness

#### `learned_selector.pkl` (~500 KB - 2 MB)
**Format**: Python pickle (scikit-learn Pipeline)  
**Contents**: Trained RandomForest with ColumnTransformer, OneHotEncoder, SimpleImputer  
**Use**: Load with `joblib.load(...)`; call `.predict(X_features)` on new data

#### `selector_classification_report.csv` (5-20 KB)
**Columns**: `action, precision, recall, f1-score, support`  
**Rows**: 10 (one per action class) + 3 (micro/macro/weighted averages)  
**Use**: Per-class accuracy metrics, identify weak predictions

#### `selector_confusion_matrix.csv` (20-30 KB)
**Format**: 10×10 matrix (predicted vs oracle action)  
**Use**: Identify which actions are confused

#### `selector_feature_importance.csv` (5-10 KB)
**Columns**: `feature_name, importance_score, importance_rank`  
**Rows**: 14-20 (one per feature)  
**Use**: Understand RF decision criteria; top-3: `arrival_gap_ms, arrival_ms, model_load_bandwidth`

#### `selector_vs_baselines_offline.csv` (10-30 KB)
**Columns**: `rate_sps, policy, oracle_utility, learned_selector_utility, fifo_utility, edf_utility, srpt_utility, ...`  
**Rows**: ~50-100 (one per rate + seed combination)  
**Use**: Compare held-out selector performance vs oracle and baselines

#### `selector_action_counts.csv` (1-5 KB)
**Columns**: `action, count, percentage`  
**Use**: Class balance analysis

#### `selector_story_focus_subset.csv` (1-3 MB)
**Rows**: Subset of high-impact samples  
**Use**: Narrative/story generation

---

### 6. Validation Checks

#### `self_checks.csv` (1-2 KB)
**Format**: Two columns: `check, pass` (all True/False)  
**Checks** (~9-15):
- `at_least_one_overloaded_scenario`
- `adaptive_cascade_used_cloud`
- `adaptive_cascade_switched_models`
- `cache_miss_observed`
- `stale_or_drop_observed`
- `all_required_figure_files_exist`
- `step1_phase_transition_exported`
- `step2_dynamic_loading_exports`
- `selector_artifacts_exported`

**Use**: Verify run completeness; all should be True

#### `self_checks_final_v3.csv` (1-2 KB)
**Format**: Same as above, final comprehensive validation

## Checkpoint Files (Model Weights)

All stored in `checkpoints/` as PyTorch `.pt` files (or pickle `.pkl`):

| File | Size | Description |
|------|------|-------------|
| `full_model.pt` | 50-100 MB | Full CNN weights (best-epoch) |
| `tiny_model.pt` | 10-20 MB | Lightweight/preview CNN weights |
| `full_model_pruned.pt` | 30-50 MB | Pruned full model |
| `tiny_model_pruned.pt` | 5-10 MB | Pruned tiny model |
| `full_model_quant.pt` | 15-25 MB | Quantized full model |
| `learned_selector.pkl` | 500 KB - 2 MB | Scikit-learn RandomForest |

**Load example**:
```python
import torch
state = torch.load('checkpoints/full_model.pt')
model = LeNetFull()
model.load_state_dict(state)
```

## Loading & Analyzing Outputs

### Python Examples

```python
import pandas as pd
import joblib

# Load main results
results = pd.read_csv('artifacts/main_results_aggregated.csv')
print(results.head())

# Load large log file (chunked)
chunks = pd.read_csv('artifacts/main_logs_all.csv', chunksize=50000)
for chunk in chunks:
    print(f"Processing {len(chunk)} rows...")

# Load selector model
selector = joblib.load('checkpoints/learned_selector.pkl')
predictions = selector.predict(new_features)

# Read config
import json
config = json.load(open('config.json'))
print(config['experiment']['seeds'])
```

### Summary Statistics

```python
# Aggregate accuracy across all conditions
logs = pd.read_csv('artifacts/main_logs_all.csv')
avg_accuracy = logs['correct'].mean()
accuracy_by_policy = logs.groupby('policy')['correct'].mean()
print(accuracy_by_policy)

# Deadline miss rate
miss_rate = (1 - logs['deadline_met']).mean()
print(f"Deadline miss rate: {miss_rate:.1%}")
```
